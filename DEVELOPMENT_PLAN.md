### ?? Известные проблемы

#### Критическая: Нет разделения ролей при регистрации
**Проблема:** При регистрации пользователя не спрашивают, кто он - учитель или ученик.

**Текущая логика:**
- `AdolescentPrototype.tsx` - только для учеников
- Нет формы регистрации для учителей
- Нет поля `role` в форме регистрации
- В `profiles` таблице есть поле `role`, но оно не заполняется

**Что происходит:**
1. Пользователь регистрируется через AdolescentPrototype
2. Создаётся запись в `profiles` с `role = null` или по умолчанию
3. При попытке зайти на `/teacher` middleware проверяет `role === 'teacher'`
4. Доступ закрыт, даже если пользователь хочет быть учителем

#### Вторичная: Нет учительского дашборда
- Маршрут `/teacher` существует, но нет UI для учителя
- Нет страницы с аналитикой по ученикам

### Этап 4: RLS-политики и тестирование

#### 4.1 Настройка RLS (Row-Level-Security)

**Таблицы:**
- `children` - учитель видит только своих учеников
- `sessions` - учитель видит сессии своих учеников
- `answers` - учитель видит ответы своих учеников

**Политики:**
```sql
-- Пример для children
CREATE POLICY "Teachers can view their students"
ON children FOR SELECT
USING (teacher_id IN (
  SELECT id FROM profiles WHERE role = 'teacher' AND auth.uid() = id
));

-- Пример для sessions
CREATE POLICY "Teachers can view their students' sessions"
ON sessions FOR SELECT
USING (child_id IN (
  SELECT id FROM children WHERE teacher_id IN (
    SELECT id FROM profiles WHERE role = 'teacher' AND auth.uid() = id
  )
));
```

#### 4.2 Комплексное тестирование

**Сценарии:**
1. Регистрация без выбора роли > редирект на `/role-selection`
2. ConsentModal без подтверждения > нельзя создать учётную запись
3. Маршруты с разными ролями (учитель, ученик, null)
4. Миграция старых пользователей с `role: null`
5. Привязка ученика к учителю через teacherCode
6. RLS: учитель не видит чужих учеников

**Команды:**
```bash
npm run dev
npm run check:full
```

### Этап 5: Интеграция AI-провайдеров (BYOK) и безопасность

#### 5.1 Хранение API-ключей на сервере

**База данных:**
```sql
CREATE TABLE api_keys (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES auth.users(id),
  provider TEXT NOT NULL,
  key TEXT NOT NULL, -- encrypted
  created_at TIMESTAMP DEFAULT NOW(),
  is_active BOOLEAN DEFAULT true
);
```

**Безопасность:**
- Использовать Edge-функции Supabase или backend для запросов к AI
- Ключи не попадают в client-side
- Шифрование ключей перед сохранением
